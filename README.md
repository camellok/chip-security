# 芯片安全专题 | Chip Security

面向客户的芯片安全例程与应用笔记，当前以昊芯 DSC 的 CSM / DCSM 代码与数据保护为起点，逐步覆盖安全 RAM、调试访问控制及应用升级中的权限管理。

已有板级验证与规划内容分别标注，后续工作见 [开发路线](docs/ROADMAP.md)。

## 获取与导入

使用 Haawking IDE 2.3.17，在独立工作空间中通过 Existing Projects 导入 `security_examples` 下的三个工程，确认目标芯片后执行构建。仓库保留源码、库文件、链接脚本和工程配置；IDE 工作空间缓存与 `Debug/` 生成物不纳入版本控制。首次克隆后请先由 IDE 生成构建文件，再按各工程 README 操作。

本地维护目录为 `D:\ApplicationNotes_Release\Chip_Security`，客户可克隆到自己的目录。更换工具链目录时应同步检查 IDE 工具链设置。完整 HEX 可能含 OTP 配置，下载前务必核对输出范围。

设备专用 OTP 备份与回读数据仅在本地保管，公开仓库只包含演示配置；请在任何 OTP 编程前自行备份目标器件。

本项目通过一组板级例程介绍安全区域划分、密码解锁和访问限制。完成培训后，应能根据应用需求安排代码与数据的位置，配置 OTP，并通过寄存器、串口日志和内存回读判断配置是否生效。

培训资料包括 demo、user guide 和 PPT，当前先完成 demo 及其验证记录。本文是例程总入口，具体操作见各工程的 README。

例程尚未定版。下文区分已验证的工程与后续设计，使用前请先确认目标芯片和对应工程的状态。

## 演示场景：厂家功能模块与产品参数

假设设备使用厂家提供的一个功能模块。APP 调用模块的公开接口，模块读取自己的产品参数，再返回处理结果。演示中只需使用简单的计算，例如 `输出 = 输入 × 系数 + 偏移`，便于直接检查结果。

| 内容 | 在例程中的作用 |
| --- | --- |
| APP | 产生测试输入，处理按键，输出 SCI 日志和 LED 状态 |
| 厂家功能模块 | 执行处理，作为代码保护对象 |
| 产品参数 | 保存模块使用的系数、偏移等只读数据，作为数据保护对象 |
| 运行状态 | 保存输入、输出及工作变量，按例程目标放入普通或安全 RAM |

通过这组对象，逐步观察功能调用、内部数据读取和调试器访问的区别。测试值及参数使用公开的演示数值；正常接口会返回处理结果，例程不把这些输出当作保密内容。

LED 和 SCI 用于确认程序是否仍在运行。数值暂停更新、读取返回零等现象，需要结合程序逻辑和当前安全状态判断，不能单凭一个观察窗口认定保护生效。

### 代码与数据布局

ex01/ex02 已分开存放模块代码和参数，为 ex03 仅对代码区增加 execute-only 准备布局。ex00 的模块及参数均在普通 APP Flash。

| 对象 | 位置 | 说明 |
| --- | --- | --- |
| APP、外设驱动及日志 | 普通 APP Flash | 用于启动、交互和结果观察 |
| 厂家模块代码 | sector4，属于 Zone1 | ex01 使用普通安全保护；ex03 再增加 execute-only |
| 产品只读参数 | sector5，属于 Zone1 | 保持普通安全属性，供同 Zone 模块按数据读取 |
| 普通运行状态 | 非安全 RAM | 便于观察输入输出；ex04 再引入安全 RAM |

当前模块计算 `output = input * 3 + 7`，用两个非安全 RAM 变量观察输入输出，保留实际参数读取。ex01/ex02 的代码在 sector4、参数在 sector5，并共用新的 Zone1 ZSB2；原 SPWM 版本的验收记录保留。构建和产物检查已通过，本轮板级回归按[简要回归表](docs/REGRESSION_EX00_EX02.md)执行。

RAM 运行代码的 Flash 加载镜像必须能被搬运代码按数据读取。安排 execute-only 区域时，需要一并检查常量、查表数据和加载镜像的位置。

### ex03 如何完成对照

ex03 使用相同的功能接口与产品参数，对照普通安全保护和 execute-only。除正常功能调用外，增加一个小型同 Zone 数据读取入口，用于检查代码区的数据读取权限。

| Zone1 锁定时的操作 | 普通安全保护 | 代码区启用 execute-only |
| --- | --- | --- |
| 执行模块代码 | 验证功能正常 | 验证功能正常 |
| 模块读取独立参数区 | 验证读取和处理正常 | 验证读取和处理正常 |
| 同 Zone 测试代码把模块代码区当数据读取 | 验证能够读出真实内容 | 验证读取受限，具体表现以板级记录为准 |
| 调试器直接读取代码区 | 验证访问受限 | 验证访问受限 |

同 Zone 数据读取是这里的主要对照。调试器在两种配置下都可能读不到锁定区域，单靠这一现象无法区分两种保护。

作为扩展实验，可将参数临时放进 execute-only 代码区，观察数据读取对功能的影响，再恢复正确布局。第一版先完成正常功能与读取限制的对照。

ex02 关注调试连接建立后的访问权限，ex08 关注获得调试访问所需的 JTAG 授权。JTAG 密码与 Zone 的 CSM 密码分别配置、分别验证；JTAG 授权成功不能代替 CSM 解锁结果。

RAMOPEN 进入和退出时都会初始化相关安全 RAM，原内容不保留。ex07 应使用可丢弃的演示数据，并从不受初始化影响的区域执行控制流程。其他例程默认不启用 RAMOPEN 或 JTAGLOCK，需要演示时再单独安排配置。

PSWDLOCK 放在 ex01 中作为开发配置与密码隐藏配置的对照，不另设例程。2800137 出厂配置允许读取密码位置，需结合 PSWDLOCK 的实际值确认；不能仅凭算法区读回受限就认定密码已隐藏。PSWDLOCK 属于固定 OTP 配置，不能设计成按键反复切换的功能。

CMAC 安全启动暂不列入正式例程。确认该器件 BootROM 的认证流程及工具支持后，再决定扩展 ex06 或新增例程。

### 内存与安全配置

模块代码与产品参数继续分区存放，便于 ex03 只对代码增加 execute-only。APP、外设驱动和日志留在普通 Flash，普通运行状态放在非安全 RAM；ex04 再引入安全 RAM。加载镜像的位置与搬运代码的 Zone 权限一并核对。

| 项目 | 2800137 的规划要求 |
| --- | --- |
| Flash 分区 | 按 2800137 的扇区和安全分组编号配置，不能沿用 28002x 的 sector 编号；若保留 `0x00610000` 至 `0x00613FFF` 地址范围，按数据手册对应扇区32至39 |
| RAM | 使用 LS0 及其安全分段，重新安排运行地址；不沿用 LS4 至 LS7 和 GS0 的内存声明 |
| USER OTP | 按该平台的 `0x00640000`、`0x00640400` Zone 基址重排固定头部和 ZSB，核对14位 LINKPOINTER 及 `0x40` 字节的 ZSB 步长 |
| 密码与状态位 | 按该平台工厂预编程位选取密码，使用匹配的 SDK 判断 CSM 状态及执行 FORCESEC |
| OTP 更新 | 固定字段一次规划；除 LINKPOINTER 的规定例外，不沿用 28002x 在已写字段中继续清位的修改方式 |
| 例程间兼容 | 实施前列出共享配置及需变更字段，确认各例程是否可以使用同一颗已配置芯片 |

这些要求用于指导建工程，尚未形成可直接烧录的 OTP 镜像。首轮验证需先保存目标芯片的初始 OTP，再确认密码、保留位及待写字段。

## 开始实验前

先阅读目标平台和工程的 README，完成基础系统验证，再进行安全配置。现有 28002x 工程的板级结果不直接适用于 2800137；TI F280025C 的对应行为也需另行验证。

编程 OTP 前，保存目标芯片的初始 OTP、待写配置与密码，并核对可编程方向。OTP 不能像普通 Flash 一样擦除恢复，项目中的 OTP 备份只代表其来源芯片。切换例程时，还需确认已有 OTP 是否兼容，不能仅凭工程编译成功就直接烧录。

构建后同时检查 map 中的运行地址、加载地址及 HEX 的实际输出范围。更新普通 Flash 时，明确区分 Flash 下载与 USER OTP 编程。ex00 不会清除芯片上已有的安全配置。

调试器可能在连接时自动解锁。进行读取对照时，记录同一时刻的区域归属、安全状态和读取结果。受保护地址返回全零，不代表真实存储内容被清零。

演示密码只用于培训。当前例程中明文存放的软件密钥和保留的开发设置，不应直接作为量产方案。
