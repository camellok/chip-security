- 模块函数实际长度28字节。反汇编确认两个 `lw` 从参数区取值，再执行 `mul` / `add`；未被替换为立即数计算。ex01/ex02代码和参数属于两个独立输出段。
- 三个工程的ramfunc运行区为 `0x00000800`～`0x000009A0`（符号上界），data为 `0x00010000`～`0x00010020`，bss清零范围为 `0x00010020`～`0x00010030`。观察量地址为 `0x00010020` / `0x00010024`。范围均在本版非安全RAM内。
- ramfunc / data 的Flash加载起点：ex00 `0x00605370` / `0x00605510`；ex01 `0x00605570` / `0x00605710`；ex02 `0x00605660` / `0x00605800`，均在APP非安全Flash内。
- 检查模板 `_init()` 的bss清零及ramfunc/data字节复制路径。ELF的实际初始化段和Flash加载地址符合上述布局，NOLOAD寄存器映射保留模板行为；不把ELF头部的默认LOAD段当作Flash数据记录。下载工具的实际ELF处理仍需板级确认。
- 三个工程各95个厂商驱动、链接脚本及库文件与用户模板逐文件SHA-256一致。`device/device.h`只选择现有XTAL配置分支，其他device模板文件保持。

## 独立OTP准备文件

ex01/ex02均执行 `Security/otp/BuildOtp.ps1` 构建成功，未进行编程。两个OTP HEX的地址和值完全一致，均仅48字节：

| 地址范围 | 内容 |
| --- | --- |
| `0x00640040`～`0x0064005F` | Z1 ZSB1密码及GRAB，32字节 |
| `0x00640450`～`0x0064045F` | Z2 ZSB1 GRAB，16字节 |

未包含两个Zone的固定头部、LINKPOINTER、PSWDLOCK、JTAGLOCK、CMAC或EXEONLY字。密码值及字段说明见[平台说明](../security_examples/hx280013x/README.md)。本轮检查只能证明源码对应的输出范围和值一致；实物OTP、槽位、保留位及编程粒度尚未确认。

参考依据：TRM V1.3第5章（表5-3、图5-1/5-2、GRABSECT3R / GRABRAM1R）、数据手册V1.4第7.1节、差异文档V1.1第7节及用户模板SDK。图5-2遗漏GRABSECT3、部分EXEONLY偏移和示例ZSB斜率存在不一致，本版不输出EXEONLY；GRABSECT3的+0x18排列仍需在实物回读和官方说明中交叉确认，不能据构建通过直接编程。
