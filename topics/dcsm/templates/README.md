# DCSM OTP 参考模板

本目录提供两种芯片的 OTP 字段骨架。默认不输出任何 OTP 配置字，保留目标芯片已有内容，不新增 Flash、RAM 安全归属，也不启用 execute-only、密码读保护或 JTAG 锁。

| 目录 | 文件及用途 |
| --- | --- |
| [hx28002x](hx28002x/README.md) | 28002x 的 Zone1、Zone2 汇编与独立 DCSM.ld |
| [hx280013x](hx280013x/README.md) | 280013x 的 Zone1、Zone2 汇编与独立 DCSM.ld |

每个平台的两份汇编按字段组列出地址、用途和注释掉的数据指令；DCSM.ld 为每组指定地址，并检查该组为空或完整输出。保留位置和未使用 ZSB 不填充。模板独立于例程，不参与例程构建；修改这里不会改变例程 Security/ 内的配置。

## 默认输出与出厂内容

“保留出厂内容”指不向这些地址提供编程数据。模板没有复制某颗芯片的 OTP 备份，也没有把密码、锁字段、启动配置或密钥假定成 0xFFFFFFFF。`<TARGET_VALUE>` 是尚未填写的注释占位符，不能直接取消注释使用。

GRAB 和 EXEONLY 字段中的 0xFFFFFFFF 仅供辨认空白编码，默认同样不输出。GRAB 的两位字段要结合两个 Zone 判断：本仓库采用的 10/10 组合表示非安全；11/11 的访问条件还与 Zone 状态有关，不能仅凭全 FF 判断。显式 10/10 参考值如下，两个 Zone 应配套核对：

| 平台 | RAM GRAB | Flash GRAB |
| --- | --- | --- |
| 28002x | 0xFFFFAAFF，LS4–LS7 | 0xAAAAAAAA，sector0–15 |
| 280013x | 0xFFFFFFAA，LS0 A–D | GRABSECT1/2：0xAAAAAAAA；GRABSECT3：0xAAAAAAFF |

这些数值没有默认启用。默认模板不会修改已有安全配置；已编程的 OTP 也无法靠输出全 FF 恢复。若芯片已经选择 ZSB2/ZSB3，模板中的 ZSB1 地址不代表能将 LINKPOINTER 回退。

## 字段依据与使用边界

字段排列依据提供的器件参考模板，以及各平台例程随附的 DriverLib inc/hw_dcsm.h。资源归属组合的说明见 [FAQ-008](../docs/faq.md)。280013x 的 GRABSECT3 ZSB+0x18 沿用当前实验接受的布局，EXEONLYSECT2 ZSB+0x2C 仍是待核对偏移，均保持关闭。模板没有把这些布局检查描述为板级验证。

需要定制时，先按目标型号和 TRM 核对字段，再填写完整字段组。链接脚本中的输入段名与本目录汇编配套，不应混用例程的 OTP 文件或链接脚本。两个平台的 OTP 地址、字段顺序、LINKPOINTER 间距不同，不能相互替换。

本目录不提供编程脚本。实际实验仍以对应例程 README 为入口，将 Flash 下载与 OTP 编程分开操作。

## 主机检查

2026-10-24，使用 Haawking IDE 2.3.17 随附的 RISC-V 汇编编译器、GNU 链接器与 llvm-readelf，分别编译两平台的 Zone1、Zone2 源文件并链接：

| 平台 | 默认 OTP 段数 | OTP 数据字节数 |
| --- | --- | --- |
| 28002x | 21 | 0 |
| 280013x | 26 | 0 |

另以临时副本将各字段组填成全 FF，检查了全部 47 组的地址、长度及数据，确认保留地址没有填充。该副本仅用于主机链接布局检查，不随模板交付。默认文件的所有 LOAD 段文件长度和内存长度均为零。本次未连接或编程硬件。
