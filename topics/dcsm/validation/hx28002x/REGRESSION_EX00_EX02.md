# ex00～ex02 简要回归

本轮将 SPWM 调整为最小产品模块，代码用于客户参考。每个工程只有输入、输出两个 RAM 观察量；模块接口为 `ProductModule_Process()`，参数为 `{3,7}`。输入1～9循环，输出应为10、13、16、19、22、25、28、31、34。

工具环境为 Haawking IDE 2.3.17，目标 HXS320F280025C_EDD。新版已在主机完成构建与产物检查；2026-10-22 开发者确认 ex00～ex02 本轮简要板级回归通过，包含 sector4/5 的锁定与解锁读取对照。原 SPWM 版本的板级记录保留在各工程 README 及 DCSM_ERRATA 中。

## 一次性配置准备

本轮沿用已有 ex01/ex02 板，尽量保留旧 OTP。现有 Z1 GRABSECT 为 `0xAAAAA9AA`，新布局需要 `0xAAAAA5AA`，0到1的冲突掩码为 `0x00000400`，因此无法覆盖首个 ZSB。

准备下一块 Z1 ZSB2，旧 ZSB1 保留。ex01/ex02 共用此配置，只需准备一次，不因切换这两个工程再消耗槽位。

ZSB2 是本轮已有开发板的测试起点，不是后续裸片演示的起点。后续会使用未使用的裸片，从 Z1 ZSB1 开始演示，再按配置兼容性决定原位追加写入或推进槽位；同配置例程共用槽位。相应 OTP 汇编、链接地址、LINKPOINTER 和步骤的整理已列入[开发路线待办](../../../../docs/ROADMAP.md)，当前工程仍保留 ZSB2 配置用于本轮测试。

| 项目 | 本轮目标 |
| --- | --- |
| Z1 三个 OTP LINKPOINTER | `0x007A0000/08/10`，值均为 `0x1FFFFFFE` |
| Z1 新 ZSB | `0x007A0060..0x007A007F` |
| EXEONLYRAM / EXEONLYSECT | 均为 `0xFFFFFFFF`，不启用 execute-only |
| GRABRAM | `0xFFFFAAFF`，LS4～LS7 保持非安全 |
| GRABSECT | `0xAAAAA5AA`，sector4/5 属于 Zone1 |
| 四个密码字 | 与 password.h 保持一致，演示值未更换 |
| Z2 | 保持原有首个 ZSB 配置；不推进 Z2 LINKPOINTER |
| 原 Z1 ZSB1 | 不输出、不擦除、不覆盖 |

编程前保存当前芯片 OTP，并确认下一块 ZSB 的现有字节与目标值兼容；其他器件不能直接沿用本板的兼容性结论。本项目不自动执行烧录。

2026-10-22 本板已分两阶段完成配置并回读确认：先写 ZSB2，三个 LINKPOINTER 保持 `0x1FFFFFFF`；再将三个指针改为 `0x1FFFFFFE`。第一阶段变化仅在 ZSB2 内，八个字段与目标一致；第二阶段仅三个指针的 bit0 从1变0，旧 ZSB1、Z2 及其他 OTP 保持不变。随后开发者确认断电独立启动、按键解锁与再次断电恢复保护均符合预期。设备回读文件仅本地保管，不提交仓库。

核对一次即可：Z1 GRABSECTR 的 sector4 `[9:8]` 和 sector5 `[11:10]` 均为 `01`，Z2 对应字段均为 `10`；当前 Z1 LINKPOINTER 有效值应为 `0x1FFFFFFE`。

## 主机检查结果

三个工程均已强制重建成功。map 和反汇编确认：

| 检查项 | 结果 |
| --- | --- |
| ex00 模块和参数 | 均位于普通 APP Flash；无 OTP 输出 |
| ex01/ex02 模块 | `0x00610000`，大小28字节 |
| ex01/ex02 参数 | `0x00614000`，8字节，内容为3、7 |
| 输入/输出 | 非安全 RAM，当前构建为 `0x00010330/0x00010334` |
| RAM 运行函数 | 保留 RAM 运行；Flash 加载镜像位于普通 APP |
| 模块参数访问 | 实际执行两次 Flash 数据读取，未折叠为常量 |
| Z1 OTP | 三个 LINKPOINTER 指向 ZSB2，配置输出在 `0x007A0060`；未输出旧 ZSB1 |
| 厂商驱动 | 未修改 C/H 代码，补充读取仍在应用层 |
| 完整 HEX | 校验和通过；ex01/ex02 各含88字节 OTP 目标数据 |

各工程使用默认构建生成的 `.hex`，不额外转换 HEX。ex00 不输出 OTP，ex01/ex02 的默认 HEX 包含 OTP 目标数据；日常仅更新程序时必须在下载工具中明确排除 USER OTP，IDE 调试加载 ELF 时也要核对实际下载范围。工具若不支持排除 OTP，不应直接执行仅更新程序的下载。

## 板级只做以下三项

统一接线：LED GPIO31、KEY GPIO9，SCIA RX/TX GPIO28/29，9600、8N1。KEY 按住至少300 ms 再松手，按住期间轮询暂停属于预期。

| 工程 | 操作和通过条件 | 本轮结果 |
| --- | --- | --- |
| ex00 | 独立上电，LED 和数值输出正常；按一次 KEY，出现 released 日志 | 2026-10-22 开发者确认通过：LED 正常；输入1～9循环且输出符合公式；按键松手打印一次，之后恢复运行 |
| ex01 | 不连调试器上电为 secure，数值仍符合公式；KEY 解锁成功；断电重启恢复 secure | 2026-10-22 开发者确认通过：LED 与计算正常，按键解锁成功，断电重启恢复 secure；ZSB2 和指针已回读确认 |
| ex02 | 做3轮锁定/解锁；锁定时 LED 继续、输入输出暂停、sector4/5 读取受限；解锁时 `Z1_CR=0x60`、参数读到3/7、输出恢复；最后断电恢复 secure | 2026-10-22 开发者确认3轮全部成功：锁定 `Z1_CR=0x08`，代码和参数读回零；解锁 `Z1_CR=0x60`，代码可读、参数为3/7；输入输出暂停与恢复正确，LED 和调试连接正常；断电恢复 secure，按键解锁后计算恢复 |

ex02 记录锁定与解锁时的 `Z1_CR`、参数区32位读数和调试连接情况即可。输入输出暂停是程序控制的结果，它们仍在非安全 RAM。若出现与旧版不同的现象，再单独定位，不为简要回归增加完整测试框架。
