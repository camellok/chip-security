# ex03 / ex04 共用配置与简要测试

目标器件为 HXS320F280025C_EDD，开发环境为 Haawking IDE 2.3.17。这两个工程沿用 `output = input * 3 + 7`，分别演示 execute-only 与安全 RAM 工作数据。ex03 的普通安全基线已收到板级日志；新共用配置和 ex04 仍待验证，代码和构建检查不替代这些测试。

## 共用内存布局

| 内容 | 地址 | 配置 |
| --- | --- | --- |
| APP、日志、启动代码、RAM 加载镜像 | 普通 APP Flash，sector0～3 | 非安全 |
| 模块代码 | sector4，`0x00610000..0x00613FFF` | Zone1，execute-only |
| 参数；ex03 的同 Zone 数据读取探针 | sector5，`0x00614000..0x00617FFF` | Zone1，普通安全保护 |
| ex04 的工作变量 | LS4，`0x00010000..0x00011FFF` | Zone1，普通安全 RAM，未启用 RAM execute-only |
| APP 的 data、bss、ramfunc | LS5～LS7，`0x00012000..0x00017FFF` | 非安全 |
| 栈 | M0/M1 | 沿用原布局 |

ex03 不使用 LS4。ex04 的安全工作段为 NOLOAD，不在启动代码的 BSS 清零及 data/ramfunc 复制范围内；由 sector4 中的模块入口先初始化，再读写。普通 APP 不负责初始化该变量。本轮不演示将代码从 Flash 搬到安全 RAM 运行，搬运流程另行安排。

## 开发板的一次性 OTP 准备

当前开发板的 ZSB2 已验证普通安全 Flash 配置。LS4 从非安全 `10` 改成 Zone1 的 `01` 存在0到1变化，因此不能原位覆盖，准备 Z1 ZSB3。ex03/ex04 共用此配置，不因切换工程再消耗槽位。后续裸片培训从 ZSB1 开始的整理任务继续保留，不直接照搬本板槽位编号。

| 地址 | 字段 | 目标值 |
| --- | --- | --- |
| `0x007A0080` | EXEONLYRAM | `0xFFFFFFFF` |
| `0x007A0084` | EXEONLYSECT | `0xFFFFFFEF`，sector4 bit4=0 |
| `0x007A0088` | GRABRAM | `0xFFFFA9FF`，LS4=`01`，LS5～7=`10` |
| `0x007A008C` | GRABSECT | `0xAAAAA5AA`，sector4/5=`01` |
| `0x007A0090` | CSMPSWD0 | `0x11111111` |
| `0x007A0094` | CSMPSWD1 | `0x02222222` |
| `0x007A0098` | CSMPSWD2 | `0x33333333` |
| `0x007A009C` | CSMPSWD3 | `0x44444444` |
| `0x007A0000/08/10` | 三个 Z1 LINKPOINTER | 均为 `0x1FFFFFFC`，选择 ZSB3 |

Z2 保持原配置，不推进指针：sector4/5 和 LS4 对应字段均为 `10`。旧 Z1 ZSB1/ZSB2 保留。

已对开发者提供的最近一份2048字节 OTP 回读核对：ZSB3 的工厂密码字为 `0x4BFFFFFF`，与本轮目标密码兼容，八个配置字未发现0到1冲突。这仅适用于该次回读所代表的器件状态；实际操作前仍需保存当前回读并核对全部待写字节。

不要自动烧录完整 HEX 来代替分阶段操作。新工程默认 HEX 含 OTP，日常下载与调试加载均须排除 USER OTP；工具不支持范围控制时先停止，不假定 HEX 记录顺序就是实际编程顺序。

## 测试顺序

1. 先保留当前 ZSB2，只下载 ex03 的程序 Flash。普通安全基线下，同 Zone 探针应能读到真实代码字，模块计算正常。保存这一次读数，后续使用同一构建的 ex03 对照。
2. 备份 OTP，先仅写 ZSB3 的 `0x007A0080..0x007A009F` 并回读校验，暂不更新指针。确认后，将三个 Z1 指针改为 `0x1FFFFFFC`，再次回读，断电上电。
3. 在新配置下测试 ex03：独立上电为 secure，计算正常；记录同 Zone 探针的代码读值并与基线比较。随后 KEY 解锁，再记录状态、计算与读取结果。execute-only 对数据读取的限制以该芯片实测为准，不能把“解锁”等同于关闭 execute-only。
4. 只更新 Flash 换成 ex04，不改 OTP。独立上电为 secure 时，模块应正常初始化和更新安全 RAM，返回结果符合公式；对比 APP 直接读取和模块返回值。按键解锁后检查 APP / 调试器读数，再锁定检查恢复限制，最后断电上电复核。

KEY 按住至少300 ms 再松手；串口9600、8N1。连接调试器可能自动解锁，观察内存时要记录同一时刻的 Z1_CR，并刷新窗口排除缓存。如果受限读产生异常而非返回零，先记录异常位置和寄存器，不直接认定为预期通过。

两例在锁定时仍调用模块，不沿用 ex02 的锁定暂停逻辑。非安全观察变量和模块正常返回值可被观察，此设计只演示指定内存的直接访问权限，不保证所有运算状态都保密。

2026-10-23 调试下载报擦除错误后，开发者提供覆盖程序 Flash 与 USER OTP 的 Intel HEX 回读，校验和和 EOF 正确。非安全 APP sector0～3 的65536字节全部为 FF，程序入口也为 FF；sector5 参数和探针的已用20字节与构建产物一致。sector4 已用28字节读回零，因 execute-only 可能限制读取，不能据此认定其被清空。先恢复程序 Flash，再做无下载调试及独立运行对照；本回读不构成 execute-only 功能通过结论。

## ex03 模块入口异常现场

2026-10-23，经开发者许可，由 HAAWKING LINK 供电，使用 downloader 随附的 OpenOCD V2.5.31 执行 reset run，等待1.5秒后暂停。未执行解锁、Flash/OTP 擦写或槽位推进。连接后立即暂停时的 PC=0 和未加载的归属寄存器不作为异常现场；以下为复位运行后重复捕获的有效结果。

| 项目 | 实测 |
| --- | --- |
| PC | `0x00600244`，当前诊断 ELF 的 `trap_entry`，指令为跳回自身 |
| mepc | `0x00610000`，`ProductModule_Process()` 入口 |
| mcause | `0x00000002`，非法指令异常 |
| mtval | `0x00000000`；不能仅凭该值判断 Flash 实际存储内容 |
| Z1_CR | `0x00000040`，UNSECURE=0 |
| Z1 GRABSECTR / GRABRAMR | `0xAAAAA5AA` / `0x0000A900`，sector4/5 和 LS4 归属符合目标 |
| Z1 EXEONLYSECTR | `0x0000FFEF`，sector4 bit4=0 |
| 三个 APP 观察量 | input=1、output=0、code_read=0 |

OpenOCD 的普通 `reg mepc/mcause/mtval` 接口未暴露这些寄存器；经 Debug Module 的只读 Access Register abstract command 读取 CSR `0x341/342/343`，各次 ABSTRACTCS 为 `0x08000002`，cmderr=0。操作涉及调试命令寄存器，不写 CPU CSR 或固件。

ELF 中模块入口原应为合法的栈调整指令；当前是模块首次取指异常，不是同 Zone 数据探针读取异常。锁定时对 sector4/5 的调试读取均为零，不能作为已擦除证据。不通过继续擦写或推进 ZSB 试错。

随后经开发者单独许可，按现有应用准备读取流程加载 OTP 头部、当前 ZSB3 并写入四个易失 CSMKEY，Z1_CR 从 `0x40` 变为 `0x60`。EXEONLYSECTR 保持 `0xFFEF`，未修改 OTP 或 Flash。解锁后 sector4 的前32字节仍读回零，不能据此确定模块实际内容；sector5 的前32字节均为 FF，与参数3/7及探针的构建字节不符。该区未启用 execute-only，在当前解锁读取条件下表现为空白，与早先保留参数的回读状态不同。本次未重写这些内容，也未在解锁后尝试执行模块；板级测试仍未通过。

再次经开发者许可，在相同复现和临时解锁后，对 `0x00610000` 执行一次入口单步。单步后 PC=`0x00600244`、mepc=`0x00610000`、mcause=`2`、mtval=`0xFFFFFFFF`，各次 abstract command 的 cmderr 均为0；未执行整个函数、擦写 Flash/OTP 或推进 ZSB。原构建入口首字为 `0xD62A7179`，并非 FF。解锁单步出现全1非法指令，结合 sector5 的空白读取与既有写入失败，强烈支持模块被擦除后未成功写回的判断；锁定时的零读值本身仍不作为存储内容证据。

后续优先确认烧录工具对已启用 execute-only 区域的擦写支持及错误码 -13 的实现含义，再恢复 sector4 模块、sector5 参数和探针。固件完整恢复前不继续做功能通过判定，不通过盲目重复全片擦写或推进新 ZSB 试错。
